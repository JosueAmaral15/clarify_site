## 📋 Overview

Implementação de sistema de templates dinâmicos no AI Processor, permitindo uso de variáveis reservadas como `{{count}}`, `{{filename}}`, `{{total}}` com suporte a operações aritméticas (+, -, *, /) em prompts.

### Problema Resolvido

**Antes**: Usuários precisavam criar prompts manualmente repetitivos para processar múltiplos arquivos:
```
"Processe o capítulo 1" (arquivo 1)
"Processe o capítulo 2" (arquivo 2)
...
```

**Depois**: Template dinâmico único funciona para todos:
```
"Processe o capítulo {{count+1}} de {{total}}: {{filename}}"
→ "Processe o capítulo 1 de 10: chapter1.txt"
→ "Processe o capítulo 2 de 10: chapter2.txt"
...
```

## 🎯 Requirements (TASKS.md linha 1061)

**Task Original**:
> Permitir no tool AI Processor a possibilidade de se utilizar palavras-chave ou palavras reservadas para escrever instruções dinâmicas e personalizadas. Por exemplo, incluir a palavra chave count, que quando colocada como {{count}}, desta maneira, faz com que haja a possibilidade de inserção de código permitido dentro de {{}}. Neste caso, se o usuário digitar {{count}}, isto quer dizer que count vai variar de 0 a N iterações, podendo seguir o seguinte exemplo de instrução: 'Quero que você processe agora o capítulo {{count+1}} do livro Meu Desafio Constante', podendo {{count+1}} aceitar também aritmética.

**Requirements Derivados**:
1. ✅ Suportar variáveis: `{{count}}`, `{{filename}}`, `{{filepath}}`, `{{total}}`
2. ✅ Suportar aritmética: `+`, `-`, `*`, `/` (divisão inteira)
3. ✅ Validação de segurança (whitelist de operadores, sem `eval()`)
4. ✅ GUI checkbox para ativar/desativar templates
5. ✅ Botão de preview para visualizar primeiro prompt
6. ✅ Tratamento de erros (undefined vars, div por zero)
7. ✅ Compatibilidade com line-by-line mode
8. ✅ 100% backward compatible (opt-in)

## 🏗️ Architecture

### Design Patterns Aplicados

1. **Strategy Pattern (GoF)**:
   - `TemplateEngine`: Diferentes estratégias de substituição
   - Simples: `{{count}}` → lookup direto
   - Aritmética: `{{count+1}}` → parsing + cálculo

2. **Template Method Pattern (GoF)**:
   - `_substitute()`: Define algoritmo de substituição
   - Steps: detect type → evaluate → format result

3. **Facade Pattern (GoF)**:
   - `render_prompt()`: Simplifica API complexa
   - Esconde `TemplateEngine + create_context + render`

4. **Low Coupling (GRASP)**:
   - `template_engine.py`: Módulo independente
   - Pode ser reutilizado fora do AI Processor

5. **High Cohesion (GRASP)**:
   - Todas funções relacionadas a templates em 1 arquivo

## 🔧 Implementation Details

### Template Syntax

| Template | Context | Output | Description |
|----------|---------|--------|-------------|
| `{{count}}` | count=0 | `0` | Zero-based file index |
| `{{count+1}}` | count=0 | `1` | One-based (human-friendly) |
| `{{count-5}}` | count=10 | `5` | Subtraction |
| `{{count*2}}` | count=3 | `6` | Multiplication |
| `{{count/2}}` | count=10 | `5` | Integer division |
| `{{filename}}` | chapter1.txt | `chapter1.txt` | File basename |
| `{{filepath}}` | /docs/ch1.txt | `/docs/ch1.txt` | Full path |
| `{{total}}` | 10 files | `10` | Total file count |

### Context Creation

```python
def create_context(file_index: int, total_files: int, file_path: str) -> Dict[str, Any]:
    return {
        'count': file_index,            # 0-based
        'total': total_files,            # Count
        'filename': os.path.basename(file_path),
        'filepath': file_path
    }
```

### Rendering Flow

```
User Prompt: "Process chapter {{count+1}} of {{total}}: {{filename}}"
              │
              v
File #0: /docs/chapter1.txt  (3 files total)
              │
              v
Context: {'count': 0, 'total': 3, 'filename': 'chapter1.txt', 'filepath': '/docs/chapter1.txt'}
              │
              v
TemplateEngine.render()
    ├─ Find: {{count+1}}   → _evaluate_arithmetic('count+1', context)  → "1"
    ├─ Find: {{total}}     → _lookup_variable('total', context)        → "3"
    └─ Find: {{filename}}  → _lookup_variable('filename', context)     → "chapter1.txt"
              │
              v
Result: "Process chapter 1 of 3: chapter1.txt"
              │
              v
Send to AI (OpenAI/Gemini/Claude)
```

## 📝 Limitations

### Current Limitations

1. **Nested Templates**: `{{{{var}}}}` não suportado (edge case raro)
2. **Float Division**: Somente divisão inteira (`10/3 = 3`, não `3.33`)
3. **Complex Expressions**: `{{count*2+1}}` requer parênteses: `{{(count*2)+1}}`  
   **Workaround**: Usar variável intermediária ou simplificar
4. **Custom Variables**: Somente built-in (`count`, `filename`, `filepath`, `total`)

### Future Enhancements (Not Implemented)

- [ ] Suporte a variáveis customizadas definidas pelo usuário
- [ ] Expressões complexas com precedência: `{{count*2+1}}`
- [ ] Template functions: `{{uppercase(filename)}}`, `{{substring(filepath, 0, 10)}}`
- [ ] Conditional templates: `{{if count > 5}}large{{else}}small{{endif}}`
- [ ] Loop templates: `{{for i in range(total)}}...{{endfor}}`

## 🎓 Lessons Learned

### What Went Well ✅

1. **Security-first design**: Whitelist approach previne vulnerabilities
2. **Comprehensive tests**: 27 tests capturaram todos os edge cases
3. **Clean API**: `render_prompt()` simplifica uso
4. **Graceful errors**: Templates inválidos não quebram aplicação
5. **GUI polish**: Preview button ajuda UX significativamente

### Challenges Faced 🔧

1. **Regex Complexity**: Balancear simplicidade vs. features
   - **Solution**: Regex simples + parsing manual
2. **Error Messages**: Tornar erros informativos sem expor internals
   - **Solution**: Mensagens formatadas como `{{UNDEFINED:var}}`
3. **Arithmetic Parsing**: Suportar operadores sem `eval()`
   - **Solution**: Split por operator + conversão manual
4. **GUI Integration**: Manter backward compatibility
   - **Solution**: Checkbox opt-in + defaults

### Best Practices Applied 📚

1. **SOLID**: Single Responsibility (TemplateEngine faz apenas templates)
2. **DRY**: Helper functions evitam duplicação
3. **KISS**: Regex simples, sem parser complexo
4. **YAGNI**: Não implementamos features não requisitadas
5. **Testing**: TDD approach (testes guiaram implementação)
