## 📋 Objetivo

Adicionar capacidade de filtrar arquivos antes do processamento IA usando as mesmas **Advanced Conditions** disponíveis em Search/Replace e Insert, permitindo que usuários enviem apenas arquivos relevantes para ChatGPT/Gemini/Claude/Perplexity.

---

## 🎯 Problema Resolvido

**Antes (v2.9.25)**:
- AI Processor processava TODOS os arquivos dos diretórios selecionados
- Sem capacidade de filtrar por tamanho, data, extensão, padrões de conteúdo
- Desperdício de tokens processando arquivos irrelevantes
- Sem controle granular sobre quais arquivos enviar

**Depois (v2.9.26)**:
- ✅ Filtros avançados antes do processamento IA
- ✅ 6 tipos de filtros: filename, path, ext, size, mtime, content
- ✅ Operadores AND/OR para combinar condições
- ✅ Regex support em todos os filtros de texto
- ✅ Scope filtering para conteúdo (brackets, braces, tags, etc.)
- ✅ Feedback claro: "Processing 3 of 10 files (7 filtered out)"
- ✅ Persistência entre sessões com QSettings

---

## 🏗️ Arquitetura

### Componentes Implementados

**1. Advanced Conditions Section (GUI)**
- **Localização**: `AIProcessorDock._setup_ui()` (após Scope Filter)
- **Layout**: QGroupBox colapsável com 3 linhas de condições iniciais
- **Componentes por linha**:
  * Field combo: `["", "filename", "path", "ext", "size", "mtime", "content"]`
  * Operator combo: `["", "contains", "not contains", "equals", "not equals", "starts with", "ends with", ">", "<", ">=", "<="]`
  * Value input: QLineEdit para padrão/valor
  * Scope combo: `["none", "brackets", "braces", "parentheses", "custom", "tag", "specific-tag", "hierarchical"]`
  * Checkboxes: Case sensitive, Regex
- **Botões**:
  * "➕ Add Condition": Adiciona linha dinamicamente (sem limite)
  * "🗑️ Clear All": Limpa todos os campos

**2. Backend Integration**
- **`_get_conditions()`**: Constrói lista de objetos `Condition` da UI
- **`_apply_advanced_conditions(files)`**: Aplica filtros usando `filter_files_by_conditions()`
- **`_process()` modificado**:
  ```python
  files = self._get_files()  # Lista completa
  filtered_files, filtered_out = self._apply_advanced_conditions(files)
  
  # Warning se nenhum arquivo passar
  if not filtered_files:
      self.show_warning("No Files Match Filters", ...)
  
  # Feedback no results panel
  self.append_result(self.text_results, 
      f"📊 Processing {len(filtered_files)} of {len(files)} files ({filtered_out} filtered out)")
  ```

**3. Persistence (QSettings)**
- **`_save_advanced_conditions_preferences()`**: Salva estado ao processar
- **`_load_advanced_conditions_preferences()`**: Carrega na inicialização
- **Chaves armazenadas**:
  * `adv_cond/enabled`: bool (se o group box está checked)
  * `adv_cond/logic`: str ("AND" ou "OR")
  * `adv_cond/rowN/field`, `rowN/operator`, `rowN/value`, `rowN/scope`, `rowN/case`, `rowN/regex`
  * `adv_cond/row_count`: int (número de linhas)

**4. Condition Logic (Reused)**
- **Importa de**: `src.core.filters`
- **Classes/Functions**:
  * `Condition` dataclass com 8 fields
  * `filter_files_by_conditions(files, conds, logic_op)` com AND/OR support
  * Suporte completo a regex, scope filtering, case sensitivity

## ⚠️ Edge Cases Tratados

1. **Nenhum arquivo passa nos filtros**:
   - ✅ Mostra warning dialog
   - ✅ Não inicia processamento
   - ✅ Feedback claro sobre quantos foram filtrados

2. **Condições vazias**:
   - ✅ Linhas com campos vazios são ignoradas
   - ✅ Se todas vazias, processa todos os arquivos

3. **Regex inválido**:
   - ✅ Tratado gracefully pela classe `Condition`
   - ✅ Retorna zero matches sem crash

4. **Advanced Conditions disabled**:
   - ✅ Checkbox no group box permite desabilitar
   - ✅ Quando disabled, processa todos (comportamento original)

5. **Persistência entre sessões**:
   - ✅ QSettings salva estado ao processar

## 📚 Padrões de Design Aplicados

### GoF Patterns

1. **Strategy** (GoF):
   - Diferentes estratégias de filtro (filename, size, content, etc.)
   - Encapsulado na classe `Condition`

2. **Chain of Responsibility** (GoF):
   - Cada condition é um handler na cadeia
   - `filter_files_by_conditions()` itera e aplica sequencialmente

3. **Observer** (Qt):
   - Signals para comunicação entre componentes
   - `adv_cond_group.toggled` signal (implícito)

4. **Facade** (GoF):
   - `_apply_advanced_conditions()` simplifica interface complexa
   - Esconde detalhes de `filter_files_by_conditions()`

### GRASP Patterns

1. **Information Expert**:
   - `Condition` class conhece como fazer matching
   - `AIProcessorDock` conhece seus próprios filtros

2. **Low Coupling**:
   - Reutiliza `src.core.filters` sem criar dependência direta
   - QSettings isola persistência

3. **High Cohesion**:
   - Métodos agrupados por responsabilidade (_add_condition_row, _clear_all_conditions, _get_conditions, _apply_advanced_conditions)

4. **Protected Variations**:
   - Interface estável mesmo se lógica de filtros mudar internamente

## 🎓 Lições Aprendidas

1. **Reutilização é Rei**:
   - Não criamos um novo sistema de filtros, reutilizamos `src.core.filters`
   - Economizou ~300 linhas de código e eliminou bugs

2. **Feedback é Crítico**:
   - Mostrar "X of Y files (Z filtered out)" foi essencial para UX
   - Usuários precisam saber quantos arquivos foram excluídos

3. **Testes Rápidos são Melhores**:
   - 21 testes em 0.33s → feedback instantâneo
   - Testes sem GUI são 100x mais rápidos que testes com GUI

4. **Persistência Melhora UX**:
   - QSettings salva preferências automaticamente
   - Usuários não precisam reconfigurar filtros a cada sessão

5. **Edge Cases Primeiro**:
   - Tratar "nenhum arquivo match" evitou confusão
   - Warning claro é melhor que silêncio
