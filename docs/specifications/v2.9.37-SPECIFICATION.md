# v2.9.37 Specification: Accessibility Labels MVP

## Executive Summary

**Release**: v2.9.37  
**Date**: 2025-12-03  
**Feature**: Apply accessibility labels to 80 widgets across 3 priority docks  
**Status**: ✅ Complete - 13/13 tests passing  
**Approach**: Incremental MVP (80 of 304 total widgets)  

## Rationale

### Why Incremental MVP?

**Problem**: Clarify has 304 widgets across 21 GUI files without accessible names, making it inaccessible to screen reader users.

**Solution**: Prioritize 3 high-traffic docks (JSON Translate, JSON Rewriter, JSON Search) for immediate impact, covering most common user workflows.

**Benefits**:
1. **User Impact**: Addresses 80 widgets in most-used features (translation, rewriting, search)
2. **Sustainable Pace**: 2-3 hour implementation vs. 8+ hours for all 304 widgets
3. **Faster Feedback**: Real user testing with screen readers (NVDA/VoiceOver) within days, not weeks
4. **Reduced Risk**: Smaller scope = easier testing, debugging, rollback
5. **Quality Focus**: More attention to label quality per widget
6. **Incremental Delivery**: Future sprints (v2.9.38-v2.9.40) complete remaining 224 widgets

### Accessibility Impact

**Before v2.9.37**:
- Screen reader users hear generic labels: "Button", "Line Edit", "Check Box"
- No context about widget purpose or current state
- Navigation relies on tab order and trial-and-error

**After v2.9.37**:
- Screen reader announces: "JSON Translate - Button - Run Translation: Execute translation on selected files"
- Clear context for every interaction
- Tab navigation enhanced with focus indicators (v2.9.35 feature)
- Users can efficiently work with translation, rewriting, and search tools

## Implementation Details

### Naming Convention

**Format**: `"Dock Name - Widget Type - Purpose"`

**Components**:
1. **Dock Name**: Human-readable dock identifier
   - Examples: "JSON Translate", "JSON Rewriter", "JSON Search"
2. **Widget Type**: Qt widget class name (simplified)
   - Button, Input, Checkbox, ComboBox, SpinBox, RadioButton, Label, TextArea
3. **Purpose**: Brief description of widget function
   - Examples: "Run Translation", "Browse Input File", "Case Sensitive"

**Examples**:
```
"JSON Translate - Button - Run Translation"
"JSON Rewriter - Checkbox - Eliminate Duplicates"
"JSON Search - Input - Search Key"
"JSON Rewriter - SpinBox - Similarity Threshold Percentage"
"JSON Search - ComboBox - Search Mode"
```

**Why This Convention?**

1. **Hierarchical Context**: Dock name provides location context
2. **Widget Type Clarity**: Users know what type of control they're interacting with
3. **Purpose Descriptiveness**: Clear action or function of the widget
4. **Screen Reader Friendly**: Reads naturally without verbosity
5. **Unique Names**: Dock name prevents collisions across similar widgets

### Code Pattern

```python
from ..accessibility_manager import AccessibilityManager

class SomeDock(BaseDock):
    def __init__(self, parent=None):
        super().__init__("Dock Name", parent)
        self._apply_accessibility()  # Call after widgets created
    
    def _apply_accessibility(self) -> None:
        """Apply accessibility labels to all widgets (v2.9.37)."""
        AccessibilityManager.set_accessible_widget(
            self.some_button,
            "Dock Name - Button - Purpose",
            "Detailed description for screen reader users"
        )
        
        AccessibilityManager.set_accessible_widget(
            self.some_input,
            "Dock Name - Input - Purpose",
            "What this input field is for"
        )
        
        # ... repeat for all widgets
```

**Key Principles**:
- Call `_apply_accessibility()` from `__init__()` after `super().__init__()`
- Group labels by widget category (inputs, buttons, checkboxes, etc.)
- Provide meaningful descriptions (not just restating the name)
- Keep descriptions concise (1-2 sentences max)

## Accessibility Guidelines for Future Implementations

### Naming Best Practices

1. **Be Specific**: "JSON Search - Button - Run Search" NOT "Search Button"
2. **Include Dock Name**: Provides location context for screen reader users
3. **Use Action Verbs**: "Run Translation", "Browse Dictionary", "Clear Results"
4. **Avoid Abbreviations**: "Variable Name" NOT "Var Name"
5. **Match Visual Label**: If button says "Browse…", accessible name should include "Browse"

### Description Best Practices

1. **Expand on Name**: Name = "Run Translation", Description = "Execute translation on selected files"
2. **Mention State**: "Current state: enabled" for dynamic widgets
3. **Provide Examples**: "e.g., 't' for t.key" in Variable Name description
4. **Explain Consequences**: "Create backup files (.bak) before modifying originals"
5. **Keep Concise**: 1-2 sentences max (screen readers read this every time!)

### Anti-Patterns to Avoid

❌ Generic names: "Button 1", "Input Field", "Checkbox"  
❌ Technical jargon without context: "Regex pattern" → "Regular expression pattern for matching text"  
❌ Redundant descriptions: Name = "Browse Button", Description = "Button to browse" (say what it browses!)  
❌ Missing descriptions: Always provide description for interactive widgets  
❌ Inconsistent formatting: Mix of CamelCase, snake_case, Title Case (stick to Title Case)

## Screen Reader Testing Guide

### Windows (NVDA)

1. **Install NVDA**: https://www.nvaccess.org/download/
2. **Launch Clarify**: `python -m clarify`
3. **Navigate Docks**: Use Tab key to move between widgets
4. **Listen to Announcements**: NVDA should read accessible name + description
5. **Test Interactions**: Activate buttons (Enter), toggle checkboxes (Space)

**Expected Announcements**:
- "JSON Translate - Button - Run Translation: Execute translation on selected files. Button"
- "JSON Rewriter - Checkbox - Eliminate Duplicates: Remove duplicate values and consolidate keys. Checkbox not checked"

### macOS (VoiceOver)

1. **Enable VoiceOver**: Cmd+F5
2. **Launch Clarify**: `python3 -m clarify`
3. **Navigate Docks**: Use Tab key or VoiceOver cursor (Control+Option+Arrow Keys)
4. **Listen to Announcements**: VoiceOver should read accessible name + role + description
5. **Test Interactions**: Activate with Control+Option+Space

**Expected Announcements**:
- "JSON Search - Input - Search Key: Search for JSON keys using dot-path notation. Edit text"
- "JSON Rewriter - SpinBox - Similarity Threshold Percentage: Percentage threshold for detecting similar objects. Spin button 0 to 100"

### Linux (Orca)

1. **Install Orca**: `sudo apt install orca`
2. **Launch Orca**: `orca` or Alt+Super+S
3. **Launch Clarify**: `python3 -m clarify`
4. **Navigate Docks**: Use Tab key or Orca navigation (Orca+KP arrows)
5. **Listen to Announcements**: Orca should read accessible name + widget type + state

**Expected Announcements**:
- "JSON Translate - Checkbox - Is File: Treat root path as single file. Checkbox not checked"
- "JSON Search - ComboBox - Search Mode: Select search mode: Key and Value, Key only, or Value only. Combo box"
